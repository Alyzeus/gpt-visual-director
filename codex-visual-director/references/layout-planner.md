# Layout Planner：实际排版与成品检查

## 选择适合的制作方式

叙事插画默认原生图像生成或编辑；布局是可观察目标，不保证像素锁定。准确长文案、表格、公式、代码原生视觉可采用确定性排版。先复用项目已有渲染代码；没有时可用本 Skill 的小型横排工具。不能交线框替代成品插画。

## 可运行模块

```text
python <skill目录>/scripts/render_layout.py <项目目录>/layout.json --out <项目目录>/renders/v001 --font <实际字体文件>
```

使用 Python、Pillow 和 fonttools；没有网络调用或模型调用。先检查依赖，缺少时报告本机具体缺项，遵从宿主已有安装授权；不静默换后端或安装大型软件。`project.py` 和 `techniques.py` 仍只需 Python 标准库。

从 `assets/layout-example.json` 复制输入，填真实文案和实际字体。示例是纯排版样例，右侧保护区没有人物素材，不能冒充完成的海报。字体不随技能分发；不假设本机存在某个字体。

## 已实现的字段

| 字段 | 实际行为 |
|---|---|
| schema_version | 当前为 1，未知字段拒绝，不静默跳过 |
| canvas.width / height | 整数像素，单边最多 8192，总像素不超过 2400 万 |
| background.color | 不透明 #RRGGBB；默认白色 |
| background.image / fit | 可选本地背景；默认 exact 要求尺寸相同；明确选择 contain 或 cover 才缩放/裁切 |
| safe_margin | 成品文字墨迹距画布边的最小像素；不靠文本框判定 |
| protected_regions | id 与 rect，检查实际文字墨迹是否侵入区域 |
| blocks[].id / text / rect | 唯一 ID、准确文案、[x,y,宽,高]；矩形必须在画布内 |
| font_file / font_index | 实际字体及集合序号；缺 font_file 时用命令行 --font |
| font_size / line_height | 整数字号与正数基线间距，实际参与渲染 |
| align / color / wrap | left、center、right；#RRGGBB；是否自动换行，默认 true |
| min_ink_height | 可选，每个非空行的最低可见墨迹高度；缺省不设此门槛 |

配置中的文件路径相对于 layout.json；命令行 --font 推荐用绝对路径。支持基础中英文横排、显式 LF 换行与自动折行。拉丁文本优先空格边界，超长内容可能按字符拆分。复杂双向文字、竖排、任意字距、描边、扭曲和自造字体不在模块范围；有需要就写项目专用实现并实际验证。

## 实际输出与验证

一次生成 `<前缀>.png`、`<前缀>.svg` 和 `<前缀>.report.json`。目标已有任一文件就拒绝覆盖，改用新版本前缀。输入错误或检查失败不留下声称通过的成品。

PNG 由实际字体渲染。先验证字体能读取、字符覆盖，再检查文本越界、安全区、行间和块间的实际墨迹重叠、保护区及已声明的最低字高。报告含每行文字、实际墨迹边界和字形度量；可读性仍需视觉判断。文本框变化时重算相邻关系。

SVG 含可修改的文字元素与嵌入的字体子集；背景若是图片仍是栅格。目标软件是否支持嵌入字体、重开后的呈现及与 PNG 的一致性需另验，不能仅因 SVG 已输出就称所有软件兼容。PNG 检查结论不代表跨渲染器像素一致，也不代表印刷、出血、色彩管理或可编辑 PSD。

生成后看全图和必要的原像素局部，逐字核对。试改一段标题，以新前缀重渲，检查变化确实生效且没有破坏保留项。运行报告只证明相应几何检查通过，D3 仍须先验证方向匹配、再看设计与工艺。

绘画图像中的人物或材质语义修改仍使用原生图像工具；本模块只处理准确文字和背景合成。合同中若要求本工具未支持的功能，先实现或明确未知，不能把数据声明当执行成功。
