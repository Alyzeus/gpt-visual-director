# Layout Planner：将布局决定落到真实成品

## 先选交付方式

- 叙事插画、概念图、绘画性主视觉：默认原生图像生成/编辑；布局是可观察的目标，不能承诺像素锁定。
- 短标题探索海报：可尝试整图生成，逐字验收；错误则定向改图。
- 精确长文案、表格、公式、代码原生矢量设计：若交付需要且有可用渲染器，采用生成主视觉与确定性文字/几何分开的方式。
- 不默认添加印刷、分层或额外源文件要求。不交空白 SVG、示意框或代码预览替代用户要求的成品插画。

布局合同是工作约定，不是已安装的排版引擎。只写所选项目渲染代码真正执行和验证的字段；不支持的字段标为未知或改选实现，不能写了就当落实。

## 最小合同

```json
{
  "canvas": {"width": 1200, "height": 1800, "unit": "px"},
  "safe_margin": 72,
  "protected_regions": [{"id": "face", "rect": [620, 260, 320, 440]}],
  "blocks": [{
    "id": "title",
    "text": "雨后的回眸",
    "rect": [72, 110, 520, 300],
    "anchor": "top_left",
    "align": "left",
    "font_file": "fonts/actual-available-font.otf",
    "font_size": 96,
    "line_height": 120,
    "color": "#FFFFFF",
    "reason": "标题处于独立留白区",
    "checks": ["文字准确", "实际渲染不越界", "不遮挡面部"]
  }]
}
```

此例中的字体路径是假设值，不能直接声称本机存在；执行前选用实际可用字体。`rect` 约定为左上角 x、y、宽、高；锚点、换行、对齐、行距必须在代码中有对应实现。示例不是本 Skill 自带渲染器的输入接口。

## 执行与检查

1. 检查项目已有渲染代码与依赖，能复用就复用。记录本机实际字体和渲染方法；缺依赖先报告或选已可用的等效实现，不擅自安装大型软件。
2. 将文案、尺寸、色彩与布局参数放入项目可修改数据，生成并运行实际渲染代码。源文件与成品明确区分。
3. 将文字宽度与换行交给实际字体渲染；文字块变化时重算相邻关系，不能只改上方留下下方间距断裂。
4. 初筛越界、保护区遮挡、意外重叠与缺字体。用最终渲染检查可见字高、墨迹间隙和裁切；不以字号或文本框证明视觉尺度。
5. 查看最终输出的全图和必要局部，逐字核对。OCR 或几何检查不能证明气质、材质和构图达标。
6. 在同一内容上试改一段标题并重渲，确认操作真正生效；然后检查其他区域。只将实际生成且能重开的格式称为可编辑源文件。

绘画图像的局部语义修改仍使用原生图像编辑。不要把确定性排版理解成用程序悄悄重画人物、修脸或替代真实图像编辑。

## 验收边界

没有实现渲染器时，合同属于设计资料，不算排版完成。PNG 是栅格成品，不自动包含可编辑文字层；SVG/HTML 中引用的照片或插画仍是栅格资产。未经专门验证，不声称具备印刷色彩管理、出血或专业印前能力。
