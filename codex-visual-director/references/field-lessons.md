# 静态视觉实作经验：参考、俯视与全身

用于参考还原、全身大透视、人物与设备互动及多轮构图修改。以下来自有限实作的观察，均为 **observed**，不是通用相机定律或稳定成功率。案例只有可移植的文字摘要；真实图片及输入日志留在原项目，未打包进 Skill。跨环境读到此文属于历史转述，不能声称本轮亲测。

## 镜头与构图

| 问题 | 方法及机制 | 本次证据与反例 |
|---|---|---|
| 高处斜拍被误当垂直俯视 | 同时检查水平表面的顶视程度、人物顶面/胸前可见关系、空间收缩方向；不能仅写“90度” | 盗贼无人机 v001 深井向画面下端延伸、正面胸部多；v003 四周向近中心收缩、头肩顶面多，俯视感改善。消失点居中是本构图采用的办法，不是垂直俯视的必要或充分条件；离轴、裁切或非对称场景不能硬套 |
| 把背景弯曲当人物透视达标 | 分别审环境畸变、前后物体尺度差、单个人体近远压缩 | v004 环境弯曲明显，但人物畸变仍受姿态/遮挡影响。大无人机不自动证明人体大透视 |
| 强俯视导致人物消失在环境里 | 把人物完整包围范围和背景深度作为不同变量控制；必要时重新投影支撑面 | v003→v004，放大人物同时保留深井及腕控，人物重新主导。约画高六成是该图局部选择，不是所有作品的默认值；包围范围不是像素面积占比，也不是放大倍率实测 |
| 全身变成“有头和两只靴” | 分开检查入画完整性和四肢连续可读性；头、双手、双脚有余量，膝髋遮挡仍记录 | v003/v004 头脚均在图内，上腿仍受遮挡，不能据此宣布全身结构完全通过；为展示全身改成斜拍也会破坏镜头硬条件 |

## 互动、保真与修改取舍

- **设备使用需要动作证据。** 盗贼无人机 v001–v004 中，食指触碰对侧腕屏、面部朝向无人机，使操作关系可读。仅在附近放一个设备不足；发光呼应不能证明真实通信。近景无人机可承担尺度对照，但过大、裁切、虚焦会抢走角色焦点，设备本体可读性需另验。
- **支撑关系不是道具出现即可通过。** 蓝白疾行者俯视稿加入安全索后，悬浮更易解释，但索下端被身体挡住，不能宣称连接和受力已核验。固定平台使支撑更清楚，也可能削弱悬空眩晕；根据首要目标取舍。
- **原图必须持续参与核验。** 盗贼本轮各次编辑都传入原始身份图，仍出现眼色、编码和装备细形漂移。实际传图可证明输入，不能保证精确还原。原参考只到大腿时，膝靴属于补全，不能称官方全身还原。
- **深入分析后仍应压缩指令。** 面部特写与首轮俯视 A/B 中，细化提示让部分特征更显著、支撑更清楚，也带来编码重构或冲击减弱。没有证据支持长提示总体更好。两组都由已加载 Skill 的会话准备，只能比较提示策略。
- **保留收益并检查代价。** 盗贼 v003 改善俯视却缩小人物，v004 再放大人物又改变桥面及脸部细节；不以局部成功推导整图通过。连续修改优先一次检验一个主要假设，不把多个未完成辅助目标一起累加。

## 可复用的小检查

针对上述任务，按需选取：第一眼主体是谁；镜头方向有什么可见证据；人体与环境的透视是否分别达标；全身完整及肢体可读是否同时成立；设备操作/支撑是否可定位；身份哪些特征正确、哪些不可核验。已有 Brief 检查足够时直接复用，不另造一整套表格。

技术失败与画面失败分开：刺客项目无护栏坐姿调用没有返回产物，不能据此否定构图。成功文件、方向通过、用户接受、独立跨会话恢复也分别记录。上述案例未做受控 Skill 消融或独立盲审，不报告因果提升比例。
