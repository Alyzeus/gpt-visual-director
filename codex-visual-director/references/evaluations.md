# 验证用例与证据边界

以下是预期行为，不是已完成测试记录。是否通过，以实际运行记录为准；本机文件工具测试与真实生图测试分开。

| ID | 场景 | 通过依据 |
|---|---|---|
| E01 | 明确要求生成一张插画 | 调用当前原生图像工具；不以提示词或 SVG 占位替代 |
| E02 | 只讨论两个设计方向，不出图 | 不调用图像工具，方向至少有两项实质差异 |
| E03 | 只审上传图 | 实际看图，给定位证据，不自动生成 |
| E04 | 原生图像工具不可用 | 报告缺口，不静默接 API、其他模型或额外服务 |
| E05 | 本地原图改耳饰颜色 | 实际加载目标并引用为编辑输入；比较目标收益与非目标偏移 |
| E06 | 工具未暴露编辑关联 | 明确 unverified，不凭视觉近似宣布已验证精确编辑 |
| E07 | 只改色后恢复任务 | 材料、文字、角色等未撤销硬条件仍在完整 Brief 中 |
| E08 | 新图更亮但目标没改善 | 可拒绝新版或选回旧稿，理由与目标对应 |
| E09 | 字号正确但可见字高不足 | 检查成品像素与文字，不能仅依据参数放行 |
| E10 | 布局声明行距和保护区 | 实际渲染执行并验收；未支持时不称布局已实现 |
| E11 | 两次无确认改善 | 重新归因与止损；不自动额外生成或推翻批准方向 |
| E12 | 回到旧版 | 旧版真实可取，选定副本存在，状态与实际文件一致 |
| E13 | 旧版缺失或文件损坏 | 报告不可恢复，不重新生一张冒充原稿 |
| E14 | 全新 GPT 上下文接续 | 仅凭项目入口读回目标、有效约束、版本和下一步；不调用生成也能先恢复 |
| E15 | 一条招式在本次看似有效 | 只记 observed；新题材测试前不称稳定经验 |
| E16 | 注册文件或状态写入成功 | 只声明文件操作成功，不推导设计通过或用户接受 |
| E17 | 用户已指定方向并授权执行 | 不强制另选三张图或逐步批准；记录 inherited 并推进 |
| E18 | 风格歧义且用户要求先选参 | 给实际看过、有空间与配色差异的候选；未授权不生成缩略图 |
| E19 | 成图精致但偏离批准方向 | 先给匹配结论和差异，优先归因方向；不靠工艺分掩盖 |
| E20 | 用自产稿验证原作还原 | 将生成版本与独立参考分开；不循环自证 |
| E21 | 布局含未知字段或字体不可用 | 明确拒绝并指出缺项，不声称功能已执行 |
| E22 | 缺字、越界、保护区或字高不合格 | 实际渲染检查失败，无伪通过成品 |
| E23 | 改标题后重渲 | 新文案实际出现，旧文件不覆盖；检查其余区域 |
| E24 | 检索招式及没有相关结果 | 返回条件、反例和证据；无命中正常，不强配手法 |
| E25 | 种子卡与历史转述 | proposed 不算已验证；reported 不改写为本轮亲测 |
| E26 | 旧 schema_version=1 项目升级 | 原版本与主版可读，新参考和检查点按需追加 |
| E27 | Brief 改为新修订 | 不自动沿用旧方向检查通过；重查受影响项 |

## 最小实际试跑

先选一个用户任务：一次明确的叙事插画、一次单目标改图、一次带短文案的海报。分别限制生成数，保留原图、实际审图、目标收益和保留项结论。不要为了完成此清单擅自触发全部生成。

《雨后的回眸》的既有试验支持一次策划—出图—对照—回退—复盘记录，但局部修改目标收益有限，不能作为本 Codex 版本已验证精确编辑的证据。此处只继承方法和失败信号，不附用户历史图像或把旧会话记录称为本机测试。

## 导演与经验库的增益单独验证

在相同 GPT、原生图像工具、Brief、参考、张数和修改上限下比较：A 直接生成，B 增加导演决策与审查；需要时另做 C，仅增加已提供的少量经验卡。保存所有候选及失败，不只挑最好的一张。

制作前保存两组指令及共同检查点；结果返回后不为其中一组追加提示或重抽，再称相同预算对照。未实际盲评时，偏好标为普通评价；记录硬错误、目标收益、非目标退步、失败调用与实际耗时。

若 A/B 都由已加载本 Skill 的同一会话选参和准备，只能称提示策略比较，不能称有/无 Skill 的因果实验。记录未控制的种子、模型版本等因素；少量样本用于定位问题，不能推导模型排名、固定提升比例或“导演一定有效”。不为完成验证擅自新增生成。
