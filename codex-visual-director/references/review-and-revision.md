# 审图、归因、定向修订与回退

## 建立证据

取得原始 Brief、当前有效方向、必要参考和实际产物。主图先完整查看，面部、手部、文字等按问题读取原像素局部；局部仍要包含判断关系所需的相邻对象。截图、裁切和测量用于检查，不改变原图。

每项记录：约束 ID、观察位置、可见事实、判断、`pass / fail / uncertain`。必要时使用像素坐标，但不强迫每张图逐像素审计。

不得混用四种结果：工具返回结果、文件可读取或解码、实际画面满足设计要求、用户接受交付。后一个不能由前一个推导。只存在外部历史文字记录时，明确说“材料报告”，不能记为本轮亲测。

## 三路检查

| 轨道 | 主要检查 | 失败处理 |
|---|---|---|
| Brief | H01 等硬条件、身份、文案、主题、尺寸及用户目的 | 硬条件失败阻止标为达标终稿 |
| Design | 批准的表达、阅读层级、人物与环境、参考规律、材质逻辑、辨识度 | 区分执行偏差与策略错误 |
| Craft | 结构、手部、边缘、字体、遮挡、间距、反射、清晰度 | 定位问题及影响，决定优先级 |

分数仅可辅助排序，不要求输出，也不建立固定自评扣分值。没有第三方或独立上下文时，应称“三视角自查”。独立 GPT 复核也可能有同源偏差；不给它作者评分和期望答案，不声称等于人工终审。

## 先分类再行动

| 类型 | 信号 | 优先动作 |
|---|---|---|
| 明确缺陷 | 能定位且违反目标 | 修一个主要问题及必要依赖 |
| 能力边界 | 同一控制反复无法兑现，无新方法 | 停止该假设，报告局限或提出替代制作方式 |
| 传图/取件问题 | 图没加载、拿错版、编辑输入无证据 | 恢复真实输入输出后再审，不猜质量 |
| 环境问题 | 缺字体、渲染器或文件权限 | 修本次必要依赖；不自动换外部服务 |
| 审美分歧 | 两种取舍各有依据 | 保留差异，请用户裁决关键选择 |

## 一轮修改协议

```yaml
parent: v001
hypothesis: 靠近门把的手仍像伸手而非放手
change: 调整手指方向及与把手的间隙
preserve: [人物五官, 服装, 镜头, 背景结构, 冷暖光比]
verify: [动作能否读懂, 手部结构, 非目标光影是否偏移]
input_relationship: unverified
action: edit_local
result: pending
```

编辑后分别写出目标项是否改善、保留项是否变化，以及无法确认的项。只做了变化而没有明确收益，可以保留旧版。更亮、更精细、更华丽不是自动接受新版的理由。

对官方服装或产品规格的精确还原，需有实际参考比对；未做逐项核验就记未知。不插入来源不明的网上配图充当手部、面部或版本证据。

## 回退不是一句裁决

1. 找到仍可获取的旧版真实文件或产物引用。
2. 本地文件可运行 `project.py select`；该操作另存选定稿，不覆盖旧稿。
3. 确认选定稿路径确实存在，并查看实际图片。
4. 更新主版本和理由，保留被否版本与其问题。

旧图失效时报告 `rollback_unavailable`，不能由提示词重新生成一张相似图再称恢复原图。`project.py` 的选定成功仅说明文件操作完成；视觉验收仍由实际检查负责。

连续两轮无确认改善时复查原因与剩余预算。无需凑足三次修改；也不因触及某轮数就强制换方向。不得用破坏性 Git 重置或强推历史实现设计回退。
